# POS Flow

## الهدف

شاشة POS مصممة للكاشير في محلات اليمن ومأرب: بيع سريع، باركود، دفع نقدي أو آجل أو جزئي، طباعة، وتعليق فواتير.

## دورة البيع

```txt
اختيار ملف POS
اختيار العميل أو عميل نقدي
مسح باركود / بحث صنف
إضافة الكمية والخصم
اختيار طريقة البيع
إدخال الدفعة
اعتماد الفاتورة في ERPNext
طباعة الإيصال عند الحاجة
```

## أوضاع البيع

- نقدي: يجب أن يغطي الدفع كامل الفاتورة.
- آجل: لا يقبل دفعة، ويحتاج حساب ذمم.
- دفعة جزئية: يقبل دفعة أقل من الإجمالي، والباقي يصبح دينًا على العميل.

## المخزون

يدعم النظام طريقتين:

- بيع مع تأثير مخزون: يمنع البيع إذا الكمية غير كافية.
- بيع بدون تأثير مخزون: مناسب للخدمات أو المحلات التي لا تدير كميات.

## اختصارات الكاشير

| الاختصار | الوظيفة |
| --- | --- |
| F1 | التركيز على البحث / الباركود |
| F2 | التركيز على مبلغ الدفع |
| F3 | دفع كامل سريع |
| F4 | تعليق الفاتورة |
| F8 | طباعة |
| F9 | إنهاء البيع |
| ESC | إغلاق الحاسبة أو إلغاء الفاتورة بعد تأكيد |

## نواقص مقصودة للمرحلة القادمة

- ربط مباشر مع Cash Drawer.
- قالب طباعة 80mm مخصص.
- سجل ورديات الكاشير.
- مرتجعات جزئية من نفس شاشة POS.

## Offline Queue v1

تمت إضافة طبقة أولى لحفظ فواتير POS محليًا عند انقطاع الاتصال.

القواعد:

- الفاتورة المحفوظة محليًا ليست معتمدة في ERPNext بعد.
- تظهر في شاشة POS كعدد فواتير بانتظار المزامنة.
- عند عودة الاتصال يمكن مزامنتها يدويًا.
- إذا فشلت المزامنة يتوقف النظام عند أول فاتورة فاشلة ويحفظ الخطأ الأخير.

التحسين القادم:

- نقل التخزين من `localStorage` إلى IndexedDB.
- إضافة Conflict Resolution.
- إضافة شاشة مراجعة للفواتير قبل المزامنة.
