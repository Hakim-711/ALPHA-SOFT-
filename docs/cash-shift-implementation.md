# Cash Shift / إغلاق الصندوق - المرحلة الأولى

تاريخ التنفيذ: 2026-05-07

## ما تم تنفيذه

تمت إضافة طبقة ورديات للـ POS حتى لا تبقى شاشة الكاشير تعمل بدون صندوق مفتوح.

المسار الجديد:

```text
/cash-shifts
```

## الربط مع ERPNext

الميزة تعتمد على مستندات ERPNext التالية:

- `POS Opening Entry`
- `POS Closing Entry`

الفكرة:

1. الكاشير يفتح وردية قبل البيع.
2. يحدد POS Profile والشركة والرصيد الافتتاحي.
3. POS يمنع اعتماد البيع إذا لا توجد وردية مفتوحة.
4. عند نهاية اليوم، تظهر شاشة جرد:
   - الافتتاحي
   - مبيعات POS
   - التحصيلات
   - المصروفات
   - المتوقع
   - المعدود فعليا
   - الفرق
5. يتم إرسال طلب إغلاق وردية إلى ERPNext.

## سلوك POS الجديد

في صفحة POS:

- يظهر زر "الوردية".
- يظهر شريط حالة الوردية.
- إذا لم توجد وردية مفتوحة، يظهر تنبيه.
- زر اعتماد البيع يتعطل حتى تفتح وردية.
- عند إنشاء الفاتورة يضاف مرجع الوردية داخل الملاحظات:

```text
POS Opening Entry: <shift-name>
```

## ملاحظات مهمة

هذه مرحلة أولى وليست نهاية نظام الوردية.

قد يرفض ERPNext فتح أو إغلاق الوردية إذا:

- المستخدم لا يملك صلاحية `POS Opening Entry`.
- المستخدم لا يملك صلاحية `POS Closing Entry`.
- POS Profile غير مضبوط.
- نسخة ERPNext لديها حقول مختلفة أو تمنع إنشاء الوردية يدويا.

إذا حدث ذلك، ستظهر رسالة الخطأ القادمة من ERPNext داخل الواجهة.

## ما تبقى للمرحلة التالية

- اختبار حي على قاعدة ERPNext الفعلية.
- إضافة قوالب طباعة إغلاق اليوم.
- إضافة سجل فروقات الصندوق.
- ربط أقوى بين Sales Invoice و POS Opening Entry إذا كانت نسخة ERPNext تدعم هذا الحقل مباشرة.
- إضافة Playwright E2E لسيناريو:
  - فتح وردية
  - بيع نقدي
  - بيع جزئي
  - صرف
  - إغلاق وردية

## تحديث لاحق: تفصيل المرتجعات والاستردادات في إغلاق الوردية

تم تحسين شاشة إغلاق الوردية حتى تفرق بين:

- مبيعات الكاشير.
- المرتجعات المسجلة خلال الوردية.
- تحصيلات العملاء.
- مصروفات الموردين.
- استرداد العملاء الناتج عن مرتجعات POS.

الأثر النقدي المهم:

- المرتجع وحده لا ينقص الصندوق دائمًا.
- سند استرداد العميل هو الذي ينقص الصندوق.
- لذلك يظهر `استرداد العملاء` كخروج مستقل ولا يتم خلطه مع مصروفات الموردين.

تم أيضًا تعديل الإغلاق بحيث إذا لم يغير الكاشير المبالغ المعدودة، يتم إرسال القيم المتوقعة كقيم معدودة بدل إرسال أصفار.
